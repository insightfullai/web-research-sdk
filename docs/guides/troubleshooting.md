# Troubleshooting and launch diagnostics

Use this guide when the SDK is installed but Insightfull does not detect the application or an expected interview does not appear. Diagnose in this order so a targeting issue is not mistaken for an installation issue.

## Capture the host-side state

The SDK exposes a stable, DOM-independent diagnostic surface:

```ts
const diagnostic = {
  version: sdk.version,
  status: sdk.status,
  initializationError: sdk.initializationError?.code ?? null,
  visitorId: sdk.currentVisitorId,
  userId: sdk.userId,
  attributes: sdk.currentAttributes,
  activeStudyId: sdk.currentStudyId,
  displayState: sdk.currentStudyDisplayState,
  lastDelivery: sdk.lastDeliveryEvaluation,
};
```

Do not include authentication tokens, payment data, health data, or sensitive free-form values in attributes or support captures.

## SDK is not detected

1. Confirm initialization runs in a browser entry point, not only during server rendering.
2. Confirm `await sdk.ready()` resolves and `sdk.status` is `"ready"`.
3. Confirm the Client ID belongs to the intended development or production environment.
4. Confirm the current hostname exactly matches an allowed domain. Ports are ignored; subdomains are not implied.
5. Confirm Content Security Policy allows the configured `apiBase` in `connect-src` and `frame-src`.
6. Open the application once, then refresh **Settings → SDK → Verify connection**. The panel reports the last signal, detected hostname, SDK version, and recent recognized events.

When `ready()` rejects, inspect `sdk.initializationError.code`. A `configuration_unavailable` error can mean the environment is missing, inactive, disallowed for the current domain, or temporarily unreachable.

## SDK is connected but no interview appears

Dry-run the expected signal first:

```ts
const evaluation = sdk.explainDelivery("checkout_completed");
console.log(evaluation.outcome, evaluation.reasonCode, evaluation.studies);
```

This does not display an interview or mutate cooldown state. Use the top-level reason and per-trigger trace to check each delivery condition:

1. The study is active and belongs to the connected environment.
2. The tracked event name or URL pattern exactly matches the configured trigger.
3. The current identity and attributes satisfy every trigger filter.
4. The participant is not inside the study cooldown window.
5. Another interview is not already active in the same SDK instance.
6. For an explicit test, use the live-app preview link generated by Insightfull. Explicit links bypass ordinary cooldown evaluation but still enforce environment and origin security.

The study's **Delivery health** panel separates evaluated, eligible, and presented attempts. It also ranks recent exclusion reasons, making a renderer failure distinguishable from an audience or event mismatch.

Track stable product-language events:

```ts
sdk.track("checkout_completed", { plan: "pro" });
```

Avoid UI implementation names such as `green_button_clicked`; they make delivery brittle when the product changes. See [Delivery diagnostics](delivery-diagnostics.md) for every stable reason code and the privacy contract.

## Custom renderer opens but cannot minimize or resume

- Call `registerIframeBridge(iframe)` after mounting the exact iframe supplied by the render payload.
- Keep the iframe mounted while minimized. Hiding the host is safe; replacing the iframe loses participant state.
- Subscribe with `onDisplayStateChange()` and unsubscribe during cleanup.
- Use payload actions—`minimize()`, `expand()`, and `dismiss()`—instead of manipulating private iframe DOM.
- Return cleanup from `renderStudy` and make it safe to call once during dismissal, reset, or destroy.

See the [custom renderer guide](customize-interview-experience.md) for complete vanilla and React examples.

## Launch-readiness checklist

Before promoting a production environment:

- verify connection from the real allowed hostname;
- identify and reset across account switches;
- confirm the expected event appears in recent activity;
- complete a real preview interview on desktop and mobile;
- verify minimize/resume preserves host and interview state;
- verify keyboard navigation, 200% zoom, reduced motion, and safe areas;
- verify dismissal restores control to the host;
- verify response completion and optional recorder finalization;
- test CSP and failure behavior with the API temporarily unavailable.

If escalation is still required, provide the environment name, current hostname, `sdk.version`, `sdk.status`, initialization error code, expected trigger name, and approximate event time. Do not send private client data.
